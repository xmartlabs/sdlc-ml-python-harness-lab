# Code of Conduct

## The standard

Be decent to the people you work with here. Concretely, that means:

- **Critique the work, not the person.** "This drops a lock ordering guarantee"
  is a review. "You clearly did not read the code" is not.
- **Assume the other person is competent and acting in good faith** until you
  have specific evidence otherwise. Most disagreements in this repo are about
  missing context, not about intelligence.
- **Accept that maintainers say no.** A rejected PR is not an insult, and a
  maintainer is not obliged to justify scope decisions at length.
- **Say what you actually verified.** Reporting "make check passes" when you
  did not run it wastes reviewer time and erodes trust faster than any bug.

Unacceptable, without much room for interpretation: harassment, sustained
personal attacks, sexualized language or imagery, publishing someone's private
information, and deliberately derailing discussions.

## Scope

This applies in issues, pull requests, commit messages, code comments, and any
space where you are representing the project.

## Reporting

This repository has no dedicated moderation mailbox, and no maintainer email is
published. Report a problem through one of these:

- **Open a private security advisory** under the repository's Security tab. It
  is not a vulnerability report, but it is the only private channel a public
  GitHub repository has, and it reaches the maintainers directly. Say up front
  that it is a conduct report.
- **GitHub's own abuse reporting**, at
  <https://github.com/contact/report-abuse>, for anything that also violates
  GitHub's Acceptable Use Policies. Use this if the person you need to report
  is a maintainer.

Reports are handled privately. You will get an acknowledgement; you may not get
a detailed account of what was done, because the other party has a reasonable
expectation of privacy too.

## Enforcement

Maintainers may edit or delete comments, close issues and pull requests, and
block accounts. The response is proportionate: a first, isolated lapse usually
gets a private word, not a ban. Repeated or deliberate behaviour escalates.

## A note on this document

This is deliberately short and specific rather than an adoption of a standard
template. It is not weaker for it — the obligations above are enforceable as
written. If your organization requires a recognized standard, the
[Contributor Covenant](https://www.contributor-covenant.org/) is the usual
choice and can be adopted in place of this file.
